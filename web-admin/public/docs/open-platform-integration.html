External Integration Guide

Connect your system through explicit public APIs and signed model notifications. Start with the operator-provided contract, then run the examples against your development installation.

1. Prepare your installation2. Authenticate and understand responses3. Run dynamic CRUD and queries4. Subscribe to model events5. Verify, persist, then acknowledge6. Handle failures and request replay

1. Prepare your installation

Ask your AuraBoot operator for the HTTPS API base URL, environment, installation client ID/secret, granted scopes, public resource and query codes, exported OpenAPI contracts/types, and the webhook signing secret. Keep each environment separate. Calls use installation credentials, never a staff account or an internal model/table identifier.

The operator creates an application and installation in /settings/api-docs, publishes explicit capabilities in /p/c/open_platform_publications, and grants the installation the required operations, rows, fields and query sources. A valid token alone does not grant model access. Some sources are read-only; only call operations advertised in your contract.

Example contract, not a built-in model: manufacturing.parts supports list/get/create/update/delete; readable/writable fields are name (required string), code (nullable string), and warehouse (required string). pid is server-generated/read-only. List permits warehouse EQ and sorting by name; max page size is at least 20. Query manufacturing.parts-by-warehouse has a required string parameter warehouse and returns the installation-visible parts. The operator must publish this example contract or adapt every sample to your actual export.

For this example request the exact scopes assigned to all five resource operations and query execution. Scope names are operator-defined. Use minimum privileges and a secret manager. Never embed client secrets in a browser/mobile app or source control.

2. Authenticate and understand responses

POST /oauth2/token accepts form-encoded grant_type=client_credentials, client_id, client_secret, and space-separated scope. HTTP Basic client authentication is also supported; do not combine Basic with form credentials.

POST /oauth2/token
Content-Type: application/x-www-form-urlencoded

grant_type=client_credentials&client_id=YOUR_CLIENT_ID&client_secret=YOUR_ENCODED_SECRET&scope=YOUR_ENCODED_SCOPES

HTTP/1.1 200 OK
Content-Type: application/json

{"access_token":"REDACTED","token_type":"Bearer","expires_in":3600,"scope":"YOUR_GRANTED_SCOPES"}

The lifetime above is illustrative: honor the returned expires_in, cache securely and refresh before expiry. There is no refresh-token flow here; request another client-credentials token. On a 401, refresh once and retry the original intent; repeated 401 needs operator attention. Do not print the token response. Send Authorization: Bearer <access_token> on public API calls. The token identifies its tenant/installation; do not add an arbitrary tenant header.

Public resource GET/POST/PATCH responses are the projected record itself, not the administration {code,data} envelope. GET/POST/PATCH return an ETag; create is 201 with Location, update/read are 200, delete is 204 with no JSON body. List returns {items,hasMore,nextCursor}; NamedQuery returns {items,total,hasMore,nextCursor,schemaVersion}. Errors carry a public code/message/requestId; retain the X-Request-Id response header for support. OAuth errors instead use {error}.

3. Run dynamic CRUD and queries

Save the following complete Bash example as crud.sh. Set the four required environment variables and the public codes from your exported contracts, then run bash crud.sh in development. It creates and later deletes its demo record. Do not enable shell tracing. Example output files and the credential form are private temporary files.

#!/usr/bin/env bash
set -euo pipefail
# Requires Bash, curl, jq and Python 3. Use a disposable development record.
: "${AURABOOT_BASE_URL:?Set the operator-provided HTTPS API origin}"
: "${AURABOOT_CLIENT_ID:?Set the installation client ID}"
: "${AURABOOT_CLIENT_SECRET:?Load the secret from your secret manager}"
: "${AURABOOT_SCOPE:?Set the exact granted scopes}"
RESOURCE=${AURABOOT_RESOURCE:-manufacturing.parts}
QUERY=${AURABOOT_QUERY:-manufacturing.parts-by-warehouse}
BASE=${AURABOOT_BASE_URL%/}
TASK_DIR=$(mktemp -d); chmod 700 "$TASK_DIR"
trap 'rm -rf "$TASK_DIR"' EXIT
# Keep credentials out of curl's argument list and terminal output.
python3 - <<'TOKEN' > "$TASK_DIR/token.form"
import os, urllib.parse
print(urllib.parse.urlencode(dict(grant_type='client_credentials',
 client_id=os.environ['AURABOOT_CLIENT_ID'], client_secret=os.environ['AURABOOT_CLIENT_SECRET'],
 scope=os.environ['AURABOOT_SCOPE'])), end='')
TOKEN
curl --fail-with-body -sS -X POST "$BASE/oauth2/token" \
 -H 'Content-Type: application/x-www-form-urlencoded' \
 --data-binary @"$TASK_DIR/token.form" > "$TASK_DIR/token.json"
TOKEN=$(jq -er '.access_token' "$TASK_DIR/token.json")
printf 'Authorization: Bearer %s\n' "$TOKEN" > "$TASK_DIR/auth.headers"
new_key() { python3 -c 'import uuid; print(uuid.uuid4())'; }
etag() { awk 'tolower($1)=="etag:" {sub(/\r$/, ""); $1=""; sub(/^ /, ""); print}' "$1"; }
# Persist each key/body before sending in a real integration. On uncertainty,
# repeat the SAME key/body/ETag; this walkthrough intentionally has no auto-retry.
CREATE_KEY=$(new_key)
curl --fail-with-body -sS -D "$TASK_DIR/create.headers" \
 -H @"$TASK_DIR/auth.headers" -H 'Content-Type: application/json' \
 -H "Idempotency-Key: $CREATE_KEY" \
 --data '{"name":"Motor","code":"M1","warehouse":"A"}' \
 "$BASE/api/open/v1/resources/$RESOURCE" > "$TASK_DIR/created.json"
PID=$(jq -er '.pid' "$TASK_DIR/created.json")
# Read one record; preserve the quotes in ETag.
curl --fail-with-body -sS -D "$TASK_DIR/get.headers" \
 -H @"$TASK_DIR/auth.headers" "$BASE/api/open/v1/resources/$RESOURCE/$PID" \
 > "$TASK_DIR/current.json"
ETAG=$(etag "$TASK_DIR/get.headers"); test -n "$ETAG"
UPDATE_KEY=$(new_key)
curl --fail-with-body -sS -X PATCH -D "$TASK_DIR/update.headers" \
 -H @"$TASK_DIR/auth.headers" -H 'Content-Type: application/json' \
 -H "Idempotency-Key: $UPDATE_KEY" -H "If-Match: $ETAG" \
 --data '{"name":"Motor revision 2","code":null}' \
 "$BASE/api/open/v1/resources/$RESOURCE/$PID" > "$TASK_DIR/updated.json"
UPDATED_ETAG=$(etag "$TASK_DIR/update.headers"); test -n "$UPDATED_ETAG"
# Filter/order/limit must be allowed by this publication and installation.
curl --fail-with-body -sS -G -H @"$TASK_DIR/auth.headers" \
 --data-urlencode 'limit=20' --data-urlencode 'sort=name' --data-urlencode 'direction=ASC' \
 --data-urlencode 'filters=[{"field":"warehouse","operator":"EQ","value":"A"}]' \
 "$BASE/api/open/v1/resources/$RESOURCE" > "$TASK_DIR/page.json"
CURSOR=$(jq -r '.nextCursor // empty' "$TASK_DIR/page.json")
if test -n "$CURSOR"; then
 curl --fail-with-body -sS -G -H @"$TASK_DIR/auth.headers" \
  --data-urlencode 'limit=20' --data-urlencode 'sort=name' --data-urlencode 'direction=ASC' \
  --data-urlencode 'filters=[{"field":"warehouse","operator":"EQ","value":"A"}]' \
  --data-urlencode "cursor=$CURSOR" "$BASE/api/open/v1/resources/$RESOURCE" \
  > "$TASK_DIR/page2.json"
fi
# NamedQuery parameters are typed JSON, never SQL or internal model codes.
curl --fail-with-body -sS -X POST -H @"$TASK_DIR/auth.headers" \
 -H 'Content-Type: application/json' \
 --data '{"parameters":{"warehouse":"A"},"limit":20}' \
 "$BASE/api/open/v1/queries/$QUERY:execute" > "$TASK_DIR/query.json"
jq '{items, hasMore, nextCursor}' "$TASK_DIR/page.json"
jq '{items, total, hasMore, nextCursor, schemaVersion}' "$TASK_DIR/query.json"
# DELETE succeeds with 204 and no JSON body. This removes the demo record.
DELETE_KEY=$(new_key)
STATUS=$(curl --fail-with-body -sS -X DELETE -o "$TASK_DIR/delete.body" -w '%{http_code}' \
 -H @"$TASK_DIR/auth.headers" -H "Idempotency-Key: $DELETE_KEY" \
 -H "If-Match: $UPDATED_ETAG" "$BASE/api/open/v1/resources/$RESOURCE/$PID")
test "$STATUS" = 204
printf 'CRUD/query walkthrough completed.\n'

Keep an opaque cursor unchanged. Subsequent list pages must preserve installation, contract, limit, filters and order; NamedQuery pages must preserve parameters and limit and add cursor to the JSON request. A changed policy/contract or expired cursor requires starting over. Filtering, sorting and parameter types are restricted by the publication; arbitrary SQL and arbitrary fields are not accepted. Omitted PATCH fields stay unchanged; explicit null clears only a nullable, writable field.

Retain the exact quoted ETag from the latest read/write. A 412 means reread and reconcile with concurrent changes before creating a new write intent; never blindly replace it with a new ETag. Persist a unique idempotency key and exact body/ETag per write intent before sending. On an ambiguous network failure repeat that exact intent. Keys are installation/route scoped, retained for 24 hours; a mismatched or expired intent returns conflict. Successful replay carries Idempotent-Replay: true. Authorization is checked again; replay cannot restore revoked access.

The TypeScript SDK supports createResource, getResourceVersioned, updateResource, deleteResource, listResources, executeQuery. SDK mutation responses wrap the record as {resource,etag,...}. Obtain the version/archive that includes these dynamic methods from your operator; an older npm release may not include them. The direct HTTP example does not depend on SDK publication.

4. Subscribe to model events

  1. The operator publishes created, updated and/or deleted events on the public resource, and grants installation read/row/field authority.
  2. Deploy a fast receiver behind a valid HTTPS endpoint. Store the signing secret separately from OAuth credentials.
  3. In the installation card, open Model notifications, select the exact event, schema version, HTTPS URL and signing secret. Create one subscription per event type. Keep the endpoint enabled.
  4. Trigger a real permitted change and inspect the installation delivery log plus your durable inbox. A generic test payload is not proof of model-event authorization or projection.

Event names are open.resource.<public-code>.created, .updated and .deleted. The machine-readable event directory is GET /api/open/v1/event-catalog with its required granted scope. Subscribe only to advertised versions. Current grants/source bindings are rechecked before every attempt/replay; withdrawn resources, revoked grants and invalid sources can prevent a send.

POST /webhooks/auraboot
Content-Type: application/json
X-Webhook-Event: open.resource.manufacturing.parts.updated
X-Webhook-Event-Version: 1
X-Webhook-Timestamp: 1792020000
X-Webhook-Delivery: delivery_public_pid
X-Webhook-Signature: sha256=LOWERCASE_HEX_HMAC

{"id":"event_public_id","type":"open.resource.manufacturing.parts.updated","schemaVersion":1,"occurredAt":"2026-10-15T00:00:00Z","subject":{"type":"manufacturing.parts","pid":"record_public_pid"},"recordVersion":2,"correlationId":"request_correlation","data":{"pid":"record_public_pid","name":"Motor revision 2","code":null,"warehouse":"A"}}

Payload data contains only the installation-visible published fields. A field omitted by policy is not a null value or a request to erase previously stored data. Deleted events describe the projected pre-delete record with a newer record version. Delivery is at least once; duplicates and out-of-order arrival are possible. Retain event IDs and per-record versions/tombstones. Do not assume every recordVersion is observed or contiguous. Model events can originate from authorized UI, imports and commands as well as public API writes.

5. Verify, persist, then acknowledge

Calculate sha256=hex(HMAC-SHA256(UTF8(secret), ASCII(timestamp) + b"." + raw_request_body)). Read the raw bytes before any JSON parser, verify a bounded timestamp window and compare signatures in constant time, then parse/validate the subscribed schema. The sample uses a receiver-chosen ±300 second window and schema version 1; synchronize clocks and adjust schema validation to your actual export. Configure a reverse proxy/body/read timeout in front of this local standard-library receiver.

Save as receiver.py, set AURABOOT_CONSUMER_KEY to a stable namespace for this installation/subscription and AURABOOT_WEBHOOK_SECRET from your secret manager. Set INBOX_DB to an absolute persistent path. Run python3 receiver.py; the HTTPS proxy forwards only the webhook path to loopback port 8099. Run python3 receiver.py --drain periodically as a separate worker. The example applies a local projection and tombstone atomically with inbox completion; it makes no external business side effects.

#!/usr/bin/env python3
"""Python 3 stdlib receiver + inbox worker; run behind a managed HTTPS proxy."""
import hashlib, hmac, json, os, sqlite3, sys, time
from http.server import BaseHTTPRequestHandler, HTTPServer
DB = os.environ.get('INBOX_DB', './auraboot-inbox.sqlite3')
# One stable consumer namespace per installation/subscription endpoint.
CONSUMER = os.environ['AURABOOT_CONSUMER_KEY']
def connect():
    db = sqlite3.connect(DB, timeout=5)
    db.execute('PRAGMA journal_mode=WAL')
    db.execute('CREATE TABLE IF NOT EXISTS inbox (consumer TEXT, id TEXT, body TEXT, done INTEGER DEFAULT 0, PRIMARY KEY(consumer,id))')
    db.execute('CREATE TABLE IF NOT EXISTS projection (consumer TEXT, resource TEXT, pid TEXT, version INTEGER, deleted INTEGER, data TEXT, PRIMARY KEY(consumer,resource,pid))')
    return db

def drain():
    db = connect()
    try:
        # One worker, short transactions. A newer event wins even if delivery is reordered.
        while True:
            with db:
                db.execute('BEGIN IMMEDIATE')
                row = db.execute('SELECT id,body FROM inbox WHERE consumer=? AND done=0 ORDER BY rowid LIMIT 1', (CONSUMER,)).fetchone()
                if row is None:
                    return
                event = json.loads(row[1]); subject = event['subject']
                deleted = int(event['type'].endswith('.deleted'))
                db.execute('INSERT INTO projection VALUES (?,?,?,?,?,?) ON CONFLICT(consumer,resource,pid) DO UPDATE SET version=excluded.version,deleted=excluded.deleted,data=excluded.data WHERE excluded.version>projection.version',
                           (CONSUMER, subject['type'], subject['pid'], event['recordVersion'], deleted, json.dumps(event['data'])))
                db.execute('UPDATE inbox SET done=1 WHERE consumer=? AND id=?', (CONSUMER, row[0]))
    finally:
        db.close()

class Receiver(BaseHTTPRequestHandler):
    def log_message(self, *_):
        pass  # Send safe metrics to your logger; never log body, secret or auth headers.
    def do_POST(self):
        if self.path != '/webhooks/auraboot':
            self.send_error(404); return
        try:
            size = int(self.headers.get('Content-Length', '0'))
            if not 0 < size <= 1048576:
                self.send_error(413); return
            raw = self.rfile.read(size)
            timestamp = self.headers.get('X-Webhook-Timestamp', '')
            signature = self.headers.get('X-Webhook-Signature', '')
            if not timestamp.isdecimal() or abs(int(time.time()) - int(timestamp)) > 300:
                self.send_error(401); return
            if len(signature) != 71 or not signature.startswith('sha256='):
                self.send_error(401); return
            keys = [os.environ['AURABOOT_WEBHOOK_SECRET']]
            if os.environ.get('AURABOOT_WEBHOOK_PREVIOUS_SECRET'):
                keys.append(os.environ['AURABOOT_WEBHOOK_PREVIOUS_SECRET'])
            message = timestamp.encode('ascii') + b'.' + raw
            valid = False
            for key in keys:
                expected = 'sha256=' + hmac.new(key.encode('utf-8'), message, hashlib.sha256).hexdigest()
                valid |= hmac.compare_digest(expected.encode('ascii'), signature.encode('ascii'))
            if not valid:
                self.send_error(401); return
            event = json.loads(raw)
            if (not isinstance(event, dict) or not isinstance(event.get('id'), str)
                or not isinstance(event.get('type'), str) or not event['type'].startswith('open.resource.')
                or not isinstance(event.get('schemaVersion'), int) or event['schemaVersion'] != 1
                or not isinstance(event.get('recordVersion'), int) or event['recordVersion'] < 1
                or not isinstance(event.get('subject'), dict)
                or not isinstance(event['subject'].get('type'), str)
                or not isinstance(event['subject'].get('pid'), str)
                or not isinstance(event.get('data'), dict)):
                self.send_error(400); return
            # Also validate the selected publication's field types/schema before consuming.
            # Commit before acknowledging. Duplicate authenticated event IDs are harmless.
            db = connect()
            try:
                with db:
                    db.execute('INSERT OR IGNORE INTO inbox(consumer,id,body) VALUES (?,?,?)',
                               (CONSUMER, event['id'], raw.decode('utf-8')))
            finally:
                db.close()
            self.send_response(204); self.end_headers()
        except (ValueError, UnicodeError, KeyError, TypeError):
            self.send_error(400)
        except sqlite3.Error:
            self.send_error(503)  # No acknowledgement if durable acceptance failed.

if __name__ == '__main__':
    if sys.argv[1:] == ['--drain']:
        drain()
    else:
        os.environ['AURABOOT_WEBHOOK_SECRET']  # Fail fast on missing signing secret.
        HTTPServer(('127.0.0.1', int(os.environ.get('PORT', '8099'))), Receiver).serve_forever()

Respond with 204 only after durable acceptance. A duplicate authenticated event returns success without a duplicate inbox row. A database failure returns 503 for redelivery. The worker transaction demonstrates idempotent local state changes; for payments/email/other external effects, use a transactional outgoing outbox and downstream idempotency keys. Acknowledging inbox storage moves subsequent business-processing retries to your own worker.

For secret rotation, temporarily verify against the current and explicitly retained previous secret; stop accepting the old one at the agreed overlap deadline. Deduplicate using the authenticated body event ID within your consumer namespace, not only the delivery header. A manual replay can repeat an event after the normal HTTP replay window; its fresh transport timestamp must still pass verification.

6. Handle failures and request replay

Public API resultCaller action
400Fix body, field, filter or parameter contract; do not retry unchanged.
401Refresh client-credentials token once; repeated failure needs operator intervention.
403 / 404Check publication/installation, scopes and row/field/source grants. 404 can hide inaccessible data. Do not probe other tenants.
409Inspect conflict/source-change code; resolve the contract or intent mismatch before a deliberate new request.
412Read the current record and reconcile concurrency; never blind retry.
429Honor Retry-After when supplied, otherwise use bounded backoff with jitter. Keep the same intent for writes.
Network timeout / 5xxOutcome may be uncertain. Retry only within a bounded client policy using the original write key/body/ETag. Do not mint a new key on every attempt.

AuraBoot → your receiver: delivery uses persisted attempts, leases and bounded exponential backoff with jitter, capped at one hour. The current maxRetries setting is the failed-attempt budget, not a promise of that many additional attempts after the first; at the configured budget a delivery enters dead_letter. HTTP errors (including 4xx/5xx) and transport failures consume that budget; SSRF/configuration rejection or revoked model authority can dead-letter immediately. Return a prompt 2xx on accepted requests; never redirect, because redirects are not followed. Do not rely on a particular exact retry schedule or cross-receiver ordering.

Slow endpoints have bounded in-flight lanes per tenant and receiver origin, shared across subscriptions; adding subscriptions does not bypass the limit. This isolation is not a production throughput guarantee. Monitor inbox lag, age, failures and duplicates as well as delivery status.

  1. Find the dead-letter event in the installation delivery log; record its delivery PID, event ID, requestId, response status and time. Do not send secrets or full personal-data payloads to support.
  2. Repair your endpoint/database/schema or ask the operator to repair publication/grants/source binding. Confirm the original event is still authorized.
  3. Ask an authorized operator to select Replay and confirm the repeated-side-effect warning. The machine token cannot administer subscriptions or replay deliveries.
  4. Verify the same event is durably accepted once by your inbox and the delivery reaches success. Replaying does not bypass source/authorization checks, create a new business event or guarantee a network send when authority is revoked.

The operator-only management route is POST /api/open-platform/installations/{installationPid}/webhook-deliveries/{deliveryPid}/replay. It uses the authenticated administration session and its CSRF policy, not OAuth machine credentials; success uses the management {code,data} envelope. Prefer the management page. Generic webhook administration also checks the exact subscription/delivery pairing.

Before enabling production, agree rate limits, payload/schema compatibility, notification latency/loss targets, endpoint secret rotation and support ownership with your operator. Local development measurements are not a production capacity/SLO commitment.
