External Integration Guide

Use your application ID and integration token to call explicitly published HTTPS APIs. The office equipment walkthrough uses the existing OSS asset-management model.

1. Receive your integration package2. Authenticate and manage tokens3. Run office-device CRUD/List and business APIs4. Subscribe to model events5. Verify and persist notifications6. Handle failures and replay7. Existing OAuth integrations

1. Receive your integration package

Ask the operator for the HTTPS API origin, environment, stable appId, one integration token, its fixed expiry or explicit permanent status, public OpenAPI/type exports, granted scopes/operations/fields/rows and support contact. Webhook signing secrets are separate from API tokens. Keep each environment separate and credentials in a server-side secret manager.

The administrator publishes the office resource in Public resources and explicit assignment/page-summary APIs in Public business APIs. In Open Platform, an authorized application owner/maintainer selects an installation, grants the required resource and business API authority, then opens Quick integration tokens. Choose a name and fixed/permanent mode, generate, and deliver the once-visible token through a secure channel. Closing or refreshing cannot reveal it again. A token alone grants no business data.

Office example contract: the operator installs OSS asset-management and publishes it as office.devices. Public fields are pid (server generated, read-only), assetCode and name (required strings), location, serialNumber, assignedTo (nullable strings), and status (read-only). New records default to available. The example grants all five operations, writable fields except status/pid, location restricted to HQ, location EQ filtering, name sorting, page size 20 or higher and created/updated/deleted events. Asset codes are caller-supplied labels here; the returned PID is the record identity.

office.devices.assign explicitly maps the native asset assignment command to this resource: required string assignedTo, effects assignedTo and status, state available → in_use. Both effects require a separate business API grant; status need not be generically writable. office.devices.page-summary binds the registered read-only page handler: integer limit → countOnPage/hasMore. These public aliases and grants must be published by your operator; they are not automatically enabled by installing the plugin. Other public contracts can use different aliases and allowed operations.

2. Authenticate and manage tokens

Send Authorization: Bearer <integration-token> directly. No OAuth exchange, extra appId header, tenant header or client secret is required. GET /api/open/v1/whoami requires openapi.profile.read; verify its applicationPid matches your delivered appId and the installation/environment is expected. appId is an identifier, not a secret or extra source of authority.

Fixed tokens: default 30 days, server range one hour through 90 days; the management form accepts 1–90 days. Permanent tokens: explicitly selected and no scheduled expiry; they remain subject to rotation cutoff, revocation, parent application/installation status and current authority. Missing mode means fixed, not permanent.

Rotation: choose a new fixed/permanent token and the old-token grace period (default 24 hours; 0 for immediate cutoff; at most 7 days). Deploy and verify the new secret before the actual old cutoff. A fixed old token never lives beyond its original expiry; a permanent old token also receives a finite cutoff. appId stays unchanged. New and old token states/cutoffs appear in the list. Single-token revoke takes effect without revoking siblings; disabling the installation/application blocks its tokens. Current scope/field/row changes apply to existing integration tokens.

Generate/rotate responses are no-store and reveal the secret once. If the response is lost, inspect the token list and revoke the uncertain token before generating a replacement; repeating the same management request key conflicts rather than revealing or silently duplicating a secret. External machine tokens cannot generate/revoke tokens, grant authority or operate replay.

Public resource GET/POST/PATCH returns a projected record, not the administration {code,data} envelope. Create returns 201/Location/ETag; read/update 200/ETag; delete 204 with no body. List returns {items,hasMore,nextCursor}. A command returns {action,resource,etag,idempotentReplay}; read-only handler output matches its exported schema. Retain X-Request-Id for support, without logging credentials.

3. Run office-device CRUD/List and business APIs

Save as crud.sh. Set AURABOOT_BASE_URL, AURABOOT_APP_ID and AURABOOT_TOKEN securely, then run bash crud.sh in development. It leaves one assigned device for review and creates/deletes a separate available device. The token needs the operator-defined resource read/write and business execute scopes plus identity scope. Never print the environment or enable shell tracing.

#!/usr/bin/env bash
set -euo pipefail
# Requires Bash, curl, jq and Python 3. Never enable shell tracing.
: "${AURABOOT_BASE_URL:?Set the operator-provided HTTPS origin}"
: "${AURABOOT_APP_ID:?Set the application ID delivered with the token}"
: "${AURABOOT_TOKEN:?Load the integration token from your secret manager}"
BASE=${AURABOOT_BASE_URL%/}
RESOURCE=office.devices
TASK_DIR=$(mktemp -d); chmod 700 "$TASK_DIR"; umask 077
trap 'rm -rf "$TASK_DIR"' EXIT
# Production requires HTTPS. Only isolated local development may use loopback HTTP.
python3 - <<'CHECK'
import os, urllib.parse
u=urllib.parse.urlsplit(os.environ['AURABOOT_BASE_URL'])
assert (u.scheme=='https' or (u.scheme=='http' and u.hostname in ('localhost','127.0.0.1')))
assert u.hostname and not u.username and not u.password and not u.query and not u.fragment and u.path in ('','/')
t=os.environ['AURABOOT_TOKEN']; assert t and '\r' not in t and '\n' not in t
CHECK
# Keep the token out of curl's command-line arguments and terminal output.
python3 - <<'AUTH' > "$TASK_DIR/auth.headers"
import os
print('Authorization: Bearer '+os.environ['AURABOOT_TOKEN'])
AUTH
new_key() { python3 -c 'import uuid; print(uuid.uuid4())'; }
etag() { awk 'tolower($1)=="etag:" {sub(/\r$/, ""); $1=""; sub(/^ /, ""); print}' "$1"; }
curl --fail-with-body -sS -H @"$TASK_DIR/auth.headers" "$BASE/api/open/v1/whoami" > "$TASK_DIR/identity.json"
jq -e --arg app "$AURABOOT_APP_ID" '.applicationPid == $app' "$TASK_DIR/identity.json" > /dev/null
# Persist each key, exact body and ETag before a write in a real integration.
# On uncertain transport failure, repeat the SAME intent. This sample has no auto-retry.
CREATE_KEY=$(new_key)
jq -n --arg code "LAPTOP-$(new_key)" '{assetCode:$code,name:"Office laptop",location:"HQ"}' > "$TASK_DIR/create.json"
curl --fail-with-body -sS -D "$TASK_DIR/create.headers" \
 -H @"$TASK_DIR/auth.headers" -H 'Content-Type: application/json' \
 -H "Idempotency-Key: $CREATE_KEY" --data-binary @"$TASK_DIR/create.json" \
 "$BASE/api/open/v1/resources/$RESOURCE" > "$TASK_DIR/created.json"
PID=$(jq -er '.pid' "$TASK_DIR/created.json")
jq -e '.status=="available" and .name=="Office laptop"' "$TASK_DIR/created.json" > /dev/null
curl --fail-with-body -sS -D "$TASK_DIR/get.headers" -H @"$TASK_DIR/auth.headers" \
 "$BASE/api/open/v1/resources/$RESOURCE/$PID" > "$TASK_DIR/current.json"
ETAG=$(etag "$TASK_DIR/get.headers"); test -n "$ETAG"
UPDATE_KEY=$(new_key)
printf '%s' '{"name":"Office laptop verified","serialNumber":null}' > "$TASK_DIR/update.json"
curl --fail-with-body -sS -X PATCH -D "$TASK_DIR/update.headers" \
 -H @"$TASK_DIR/auth.headers" -H 'Content-Type: application/json' \
 -H "Idempotency-Key: $UPDATE_KEY" -H "If-Match: $ETAG" \
 --data-binary @"$TASK_DIR/update.json" "$BASE/api/open/v1/resources/$RESOURCE/$PID" > "$TASK_DIR/updated.json"
ETAG=$(etag "$TASK_DIR/update.headers"); test -n "$ETAG"
jq -e '.name=="Office laptop verified" and .serialNumber==null' "$TASK_DIR/updated.json" > /dev/null
# Walk all authorized pages; the cursor is opaque and is not a synchronization watermark.
CURSOR=''; FOUND=0
while :; do
 ARGS=(--data-urlencode 'limit=20' --data-urlencode 'sort=name' --data-urlencode 'direction=ASC'
       --data-urlencode 'filters=[{"field":"location","operator":"EQ","value":"HQ"}]')
 if test -n "$CURSOR"; then ARGS+=(--data-urlencode "cursor=$CURSOR"); fi
 curl --fail-with-body -sS -G -H @"$TASK_DIR/auth.headers" "${ARGS[@]}" \
  "$BASE/api/open/v1/resources/$RESOURCE" > "$TASK_DIR/page.json"
 if jq -e --arg pid "$PID" '.items | any(.pid==$pid)' "$TASK_DIR/page.json" > /dev/null; then FOUND=1; fi
 if test "$(jq -r '.hasMore' "$TASK_DIR/page.json")" = false; then break; fi
 NEXT=$(jq -er '.nextCursor | select(length>0)' "$TASK_DIR/page.json"); test "$NEXT" != "$CURSOR"; CURSOR=$NEXT
done
test "$FOUND" = 1
# Explicit business API: native assignment state transition, same resource ETag and grant.
ASSIGN_KEY=$(new_key)
jq -n --arg pid "$PID" --arg person "${AURABOOT_ASSIGNED_TO:-External integration operator}" \
 '{targetPid:$pid,input:{assignedTo:$person}}' > "$TASK_DIR/assign.json"
curl --fail-with-body -sS -D "$TASK_DIR/assign.headers" \
 -H @"$TASK_DIR/auth.headers" -H 'Content-Type: application/json' \
 -H "Idempotency-Key: $ASSIGN_KEY" -H "If-Match: $ETAG" --data-binary @"$TASK_DIR/assign.json" \
 "$BASE/api/open/v1/actions/office.devices.assign:execute" > "$TASK_DIR/assigned.json"
jq -e '.resource.status=="in_use" and .idempotentReplay==false' "$TASK_DIR/assigned.json" > /dev/null
# A registered no-target, read-only handler counts only one authorized page, not total inventory.
curl --fail-with-body -sS -H @"$TASK_DIR/auth.headers" -H 'Content-Type: application/json' \
 --data '{"input":{"limit":20}}' "$BASE/api/open/v1/actions/office.devices.page-summary:execute" > "$TASK_DIR/summary.json"
jq -e '.countOnPage>=1 and (.hasMore|type)=="boolean"' "$TASK_DIR/summary.json" > /dev/null
# Delete a separate AVAILABLE example; preserve the assigned device as a reviewable business trace.
jq -n --arg code "TEMP-$(new_key)" '{assetCode:$code,name:"Temporary office device",location:"HQ"}' > "$TASK_DIR/delete-example.json"
TEMP_KEY=$(new_key)
curl --fail-with-body -sS -D "$TASK_DIR/temp.headers" -H @"$TASK_DIR/auth.headers" \
 -H 'Content-Type: application/json' -H "Idempotency-Key: $TEMP_KEY" \
 --data-binary @"$TASK_DIR/delete-example.json" "$BASE/api/open/v1/resources/$RESOURCE" > "$TASK_DIR/temp.json"
TEMP_PID=$(jq -er '.pid' "$TASK_DIR/temp.json"); TEMP_ETAG=$(etag "$TASK_DIR/temp.headers"); test -n "$TEMP_ETAG"
DELETE_KEY=$(new_key)
STATUS=$(curl --fail-with-body -sS -X DELETE -o "$TASK_DIR/delete.body" -w '%{http_code}' \
 -H @"$TASK_DIR/auth.headers" -H "Idempotency-Key: $DELETE_KEY" -H "If-Match: $TEMP_ETAG" \
 "$BASE/api/open/v1/resources/$RESOURCE/$TEMP_PID")
test "$STATUS" = 204
printf 'Office CRUD/List, assignment and page summary completed.\n'

Keep cursor, filters, sorting, direction and page limit unchanged between pages; a changed contract/policy or expired cursor requires starting over. This list is not a stable full-data snapshot. List plus events does not guarantee gap-free synchronization; watermarks, incremental catchup and snapshot boundaries are outside this release.

Omitted PATCH fields stay unchanged; explicit null clears only nullable writable fields. Preserve the exact quoted resource ETag. For every write, persist a unique key, exact body and applicable ETag before sending; on an ambiguous transport outcome resend that same intent. Keys are installation/route scoped with a 24-hour retention boundary; do not issue a new key until the previous outcome is reconciled. Mismatch/expiry conflicts; successful replay has Idempotent-Replay: true. Authorization is rechecked and replay cannot restore revoked access. A 412 requires reread and business reconciliation, never a blind retry with a newer ETag.

Business APIs are explicit POST contracts, not internal controller URLs or arbitrary scripts. Assignment uses the bound office resource ETag, current row/field grants, declared effects and native state rules. Read-only handlers have no target, If-Match or Idempotency-Key. Exported NamedQuery APIs remain available where separately published; they accept typed parameters, not SQL. The TypeScript SDK supports direct access-token configuration and resource CRUD/List/query methods; use direct HTTP for the business API calls shown here.

4. Subscribe to model events

  1. The operator publishes the office resource events and grants installation read/row/field authority and the event directory scope.
  2. Deploy the receiver behind valid HTTPS and retain its signing secret separately from API tokens.
  3. In the installation card, open Model notifications; select the advertised event/schema version, HTTPS endpoint and signing secret. Create subscriptions for created, updated and deleted as required.
  4. Trigger real CRUD or assignment, inspect delivery status and confirm the event in your durable inbox. A generic test notification does not prove model projection or authority.

GET /api/open/v1/event-catalog lists currently available event contracts with its required scope. Events are open.resource.office.devices.created, .updated and .deleted, schema version 1 in this example. Current publication, source and installation authority is checked for every attempt/replay. Tokens and signing secrets have separate lifecycles.

POST /webhooks/auraboot
Content-Type: application/json
X-Webhook-Event: open.resource.office.devices.updated
X-Webhook-Event-Version: 1
X-Webhook-Timestamp: 1792020000
X-Webhook-Delivery: delivery_public_pid
X-Webhook-Signature: sha256=LOWERCASE_HEX_HMAC

{"id":"event_public_id","type":"open.resource.office.devices.updated","schemaVersion":1,"occurredAt":"2026-10-15T00:00:00Z","subject":{"type":"office.devices","pid":"record_public_pid"},"recordVersion":2,"correlationId":"request_correlation","data":{"pid":"record_public_pid","assetCode":"LAPTOP-001","name":"Office laptop","status":"in_use","location":"HQ","assignedTo":"External integration operator"}}

Payload contains only currently visible published fields. An omitted field is not a null or an instruction to erase an existing business value. Deleted events contain the projected pre-delete record with a newer version. Delivery is at least once, with possible duplicates and reordering. Retain event IDs and per-record versions/tombstones; versions need not be contiguous. Authorized UI/import/command changes can also produce events. When grants shrink, your own retention policy must remove no-longer-authorized stored data; replay is not a historical permission snapshot.

5. Verify and persist notifications

Verify sha256=hex(HMAC-SHA256(UTF8(secret), ASCII(timestamp)+b"."+raw_body)) before JSON parsing. Compare in constant time and enforce a clock window (sample ±300 seconds). Validate event type, schema, resource identity, version and projected field types. The example below targets the office contract; adapt the whitelist and required fields to your actual export/grants. Keep clocks synchronized. Configure request/body/read timeouts and concurrency at the HTTPS reverse proxy.

Save as receiver.py. Set stable AURABOOT_CONSUMER_KEY, secret-manager AURABOOT_WEBHOOK_SECRET and an absolute persistent INBOX_DB path. Run python3 receiver.py behind the proxy forwarding only /webhooks/auraboot to loopback 8099, and periodically run python3 receiver.py --drain as a separate worker. Optional AURABOOT_WEBHOOK_PREVIOUS_SECRET requires an explicit Unix AURABOOT_WEBHOOK_PREVIOUS_UNTIL cutoff; remove the old key after rotation.

#!/usr/bin/env python3
"""Python 3 stdlib office-device receiver and atomic inbox worker; HTTPS proxy required."""
import hashlib, hmac, json, os, sqlite3, stat, sys, time
from http.server import BaseHTTPRequestHandler, HTTPServer
DB = os.environ['INBOX_DB']
CONSUMER = os.environ['AURABOOT_CONSUMER_KEY']
SECRET = os.environ['AURABOOT_WEBHOOK_SECRET'].encode('utf-8')
assert os.path.isabs(DB) and CONSUMER and SECRET, 'Persistent absolute DB path and secrets required'
RESOURCE = 'office.devices'
TYPES = {f'open.resource.{RESOURCE}.{suffix}' for suffix in ('created','updated','deleted')}
FIELDS = {'pid','assetCode','name','status','location','serialNumber','assignedTo'}
def connect():
    # Create private storage and reject an unsafe existing path instead of changing its permissions.
    try:
        fd = os.open(DB, os.O_CREAT | os.O_EXCL | os.O_WRONLY, 0o600); os.close(fd)
    except FileExistsError:
        info = os.lstat(DB)
        if not stat.S_ISREG(info.st_mode) or info.st_mode & 0o077:
            raise ValueError('Inbox storage must be a private regular file')
    db = sqlite3.connect(DB, timeout=5)
    db.execute('PRAGMA journal_mode=WAL')
    db.execute('CREATE TABLE IF NOT EXISTS inbox (consumer TEXT, id TEXT, body BLOB, done INTEGER DEFAULT 0, PRIMARY KEY(consumer,id))')
    db.execute('CREATE TABLE IF NOT EXISTS projection (consumer TEXT, resource TEXT, pid TEXT, version INTEGER, deleted INTEGER, data TEXT, PRIMARY KEY(consumer,resource,pid))')
    return db

def validate(event, headers):
    if not isinstance(event, dict) or event.get('type') not in TYPES:
        raise ValueError('Unsubscribed event')
    if (headers.get('X-Webhook-Event') != event['type'] or headers.get('X-Webhook-Event-Version') != '1'
        or type(event.get('schemaVersion')) is not int or event['schemaVersion'] != 1
        or type(event.get('recordVersion')) is not int or not 1 <= event['recordVersion'] <= 9223372036854775807):
        raise ValueError('Schema or version mismatch')
    subject, data = event.get('subject'), event.get('data')
    if not isinstance(subject, dict) or subject.get('type') != RESOURCE or not isinstance(data, dict):
        raise ValueError('Invalid resource')
    for identity in (event.get('id'), subject.get('pid')):
        if not isinstance(identity,str) or not 1 <= len(identity) <= 200 or any(ord(c)<33 for c in identity):
            raise ValueError('Invalid identity')
    if set(data) - FIELDS or data.get('pid') != subject['pid']:
        raise ValueError('Unexpected field or identity')
    for key, value in data.items():
        if value is not None and (not isinstance(value,str) or len(value)>10000):
            raise ValueError('Invalid field type')
    # Adapt required fields to the actual projected contract and current installation policy.
    if any(key in data and data[key] is None for key in ('pid','assetCode','name')):
        raise ValueError('Required field cannot be null')

def drain():
    db = connect()
    try:
        while True:
            with db:
                db.execute('BEGIN IMMEDIATE')
                row = db.execute('SELECT id,body FROM inbox WHERE consumer=? AND done=0 ORDER BY rowid LIMIT 1', (CONSUMER,)).fetchone()
                if row is None: return
                event = json.loads(row[1]); subject = event['subject']
                deleted = int(event['type'].endswith('.deleted'))
                db.execute('INSERT INTO projection VALUES (?,?,?,?,?,?) ON CONFLICT(consumer,resource,pid) DO UPDATE SET version=excluded.version,deleted=excluded.deleted,data=excluded.data WHERE excluded.version>projection.version',
                    (CONSUMER,subject['type'],subject['pid'],event['recordVersion'],deleted,json.dumps(event['data'])))
                db.execute('UPDATE inbox SET done=1 WHERE consumer=? AND id=?', (CONSUMER,row[0]))
    finally: db.close()

class Receiver(BaseHTTPRequestHandler):
    def log_message(self, *_): pass  # Never log bodies, secrets or authorization headers.
    def do_POST(self):
        if self.path != '/webhooks/auraboot': self.send_error(404); return
        try:
            length = int(self.headers.get('Content-Length','0'))
            if not 0 < length <= 1048576: self.send_error(413); return
            raw = self.rfile.read(length)
            if len(raw) != length: raise ValueError('Incomplete body')
            stamp = self.headers.get('X-Webhook-Timestamp','')
            if not stamp.isascii() or not stamp.isdecimal() or len(stamp)>12 or abs(time.time()-int(stamp))>300:
                self.send_error(401); return
            signature = self.headers.get('X-Webhook-Signature','')
            if len(signature)!=71 or not signature.startswith('sha256='):
                self.send_error(401); return
            keys = [SECRET]
            previous = os.environ.get('AURABOOT_WEBHOOK_PREVIOUS_SECRET')
            # Previous signing key is accepted only until an explicit local Unix deadline.
            if previous and time.time() < int(os.environ['AURABOOT_WEBHOOK_PREVIOUS_UNTIL']): keys.append(previous.encode('utf-8'))
            if not any(hmac.compare_digest(signature, 'sha256='+hmac.new(k,stamp.encode('ascii')+b'.'+raw,hashlib.sha256).hexdigest()) for k in keys):
                self.send_error(401); return
            event = json.loads(raw); validate(event,self.headers)
            db = connect()
            try:
                with db:
                    old = db.execute('SELECT body FROM inbox WHERE consumer=? AND id=?', (CONSUMER,event['id'])).fetchone()
                    if old is not None:
                        # Same event ID must retain its record identity and version. Projection may narrow on replay.
                        prior = json.loads(old[0])
                        if any(prior.get(k)!=event.get(k) for k in ('type','subject','recordVersion','schemaVersion')):
                            raise ValueError('Conflicting duplicate event')
                    else: db.execute('INSERT INTO inbox(consumer,id,body) VALUES(?,?,?)', (CONSUMER,event['id'],raw))
            finally: db.close()
            self.send_response(204); self.end_headers()  # Durable inbox committed before acknowledgement.
        except (ValueError,UnicodeError,KeyError,TypeError): self.send_error(400)
        except sqlite3.Error: self.send_error(503)

if __name__=='__main__':
    if sys.argv[1:]==['--drain']: drain()
    elif sys.argv[1:]: raise SystemExit('Usage: receiver.py [--drain]')
    else: HTTPServer(('127.0.0.1',int(os.environ.get('PORT','8099'))),Receiver).serve_forever()

A 204 follows committed inbox storage; storage errors return 503 for retry. Duplicate identity/version is accepted once. The worker atomically updates the latest projected event view and inbox completion, keeps tombstones and ignores older versions. This local event view contains exactly the latest received projection; it is not a full synchronized business record or an erasure protocol. Add your own transactional outbox/idempotency for external business side effects.

6. Handle failures and replay

ResultExternal caller action
400Correct inputs against the exported contract; do not repeatedly resend unchanged invalid data.
401 / 403For direct integration tokens, ask the operator to check expiry, cutoff, revoke, parent status and current grants. Do not attempt an OAuth exchange with that token.
409 / 412Reconcile intent/source/contract conflict or reread concurrent data. Never silently invent a new write key or ETag.
429Honor Retry-After where supplied, apply bounded backoff/jitter and preserve the original write intent.
Timeout / 5xxBound retries and keep the same write intent; investigate persistent errors with requestId and safe metadata.

Webhook failures retry with exponential backoff and jitter capped at one hour. maxRetries is the failed-attempt budget, not that many additional attempts. HTTP 4xx/5xx and transport failures consume it; SSRF/configuration or revoked model authority may dead-letter immediately. Redirects are not followed. Return a fast 2xx only after durable acceptance. Per-tenant receiver-origin lanes bound in-flight requests across subscriptions; notification development measurements are not a production throughput/SLO promise.

  1. Find the failed/dead-letter delivery in the installation log; retain delivery/event IDs, requestId, status and time without secrets or sensitive payloads.
  2. Repair receiver/database/schema or ask the operator to repair source/publication/grants.
  3. An authorized operator opens Replay, reviews the repeated-side-effect warning and confirms. Machine tokens cannot administer replay.
  4. Confirm the same event is accepted once in the inbox and the delivery succeeds. Replay does not create a new business event or bypass current authorization.

Operator route: POST /api/open-platform/installations/{installationPid}/webhook-deliveries/{deliveryPid}/replay, using the administration session and its CSRF policy, with management envelope. Prefer the page. Agree production rate/latency/support and schema compatibility separately.

7. Existing OAuth integrations

Existing client-credentials integrations remain supported: POST /oauth2/token with form-encoded grant_type=client_credentials, client_id, client_secret and granted space-separated scope, or use HTTP Basic client authentication without duplicate form credentials. Cache the returned access_token securely and honor expires_in. There is no refresh-token flow; request another client-credentials token. On 401, exchange once and retry the same intent; repeated failures need operator attention. Installation scope edits revoke existing OAuth tokens and require a new exchange. Permanent integration tokens do not change OAuth expiry or requested-scope limits.

Reference: Open Platform API reference. Obtain tenant-specific resource, query and business API contracts from the operator. This public guide contains no credentials.
