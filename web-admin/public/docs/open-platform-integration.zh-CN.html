外部系统接入指南

使用 appId 和集成 token，直接调用已发布的 HTTPS 接口。本文以已有的办公设备模型为例，依次完成管理员开通、设备增删改查和列表、设备分配、事件订阅与失败恢复。

1. 管理员准备与交付2. 认证与 token 管理3. 办公设备 CRUD/List 与业务接口4. 订阅模型事件5. 验签与可靠接收6. 失败重试、死信与重放7. 既有 OAuth 接入

1. 管理员准备与交付

谁来操作：我们的管理员负责发布接口、创建应用和环境安装、授权及签发 token；外部开发者负责调用接口和部署通知接收端。机器 token 不能管理权限、生成 token 或执行通知重放。

  1. 通过正式插件入口安装 OSS asset-management。在公共资源发布中选择设备来源 tasset_asset，以 office.devices 发布，明确字段、五种操作、过滤/排序能力和事件。
  2. 在公共业务接口中发布 office.devices.assign 和 office.devices.page-summary，分别绑定原生设备分配命令和已注册只读页面统计 Handler。安装插件不会自动公开接口。
  3. 进入“设置 → 开放平台”，创建外部应用，记录 appId，再为目标环境创建安装。授予 openapi.profile.read、openapi.events.read、office.devices.read、office.devices.write、office.devices.assign.execute、office.devices.page-summary.execute；这些 scope 以本例发布的合同为前提。
  4. 在安装的数据授权中选择允许的操作、可读/可写字段及行范围。本例允许五种操作，除 status/pid 外的字段可写，行范围限定 location = HQ；单独授予设备分配和页面统计业务接口，分配影响字段为 assignedTo/status。
  5. 打开安装的“快捷接入令牌”，填写用途名称，选择定期或永久，生成后通过安全渠道交付仅显示一次的 token。

交付清单：HTTPS API 地址、环境、稳定 appId、token、明确到期时间或永久标识、已授权操作/字段/行范围、下载的 OpenAPI/类型合同、支持联系人。本指南可匿名阅读，不包含任何真实凭证。每个环境独立保管凭证，外部服务将其存入服务端密钥管理系统。

办公设备字段：pid 为服务端生成的只读标识；assetCode 和 name 为必填字符串；location、serialNumber、assignedTo 为可空字符串；status 只读，新设备默认 available。本例允许 location EQ 过滤、name 排序、每页至少 20 条及 created/updated/deleted 事件。设备编号是调用方标签，返回的 PID 才是记录身份。

office.devices.assign 要求字符串 assignedTo，将状态从 available 改为 in_use；必须单独授予其影响字段权限，无需让 status 成为通用可写字段。office.devices.page-summary 接受整数 limit，返回 countOnPage/hasMore，只统计一个授权页面。其他接口合同可以使用不同别名和操作。

2. 认证与 token 管理

直接发送 Authorization: Bearer <token>，无需 OAuth 换取、额外 appId/租户请求头或 client secret。先调用 GET /api/open/v1/whoami（需要 openapi.profile.read），核对 applicationPid 等于交付的 appId，并确认安装和环境。appId 是公开标识，不能用来切换 token 绑定的租户或环境。

定期 token：默认 30 天，管理页可选 1–90 天，服务端允许 1 小时至 90 天。永久 token：必须显式选择，无自然到期时间，但仍受轮换截止、撤销、应用/安装状态及当前授权约束。未选择永久模式不会意外生成永久 token。

轮换：管理员选择新 token 的定期/永久模式及旧 token 宽限期，默认 24 小时，可选 0（立即截止），最长 7 天。新 token 立即可用，appId 不变。外部在旧 token 截止前替换并验证新 token；定期旧 token 不超过原到期时间，永久旧 token 也会获得有限截止时间。列表显示状态与实际截止时间。

撤销与撤权：单独撤销不影响同安装的其他 token；停用应用/安装将阻断所属 token。操作、scope、行或字段授权变化立即影响既有集成 token 的后续请求。已经通过鉴权的在途事务不承诺回滚。

生成/轮换响应为 no-store，原文只显示一次；关闭或刷新后不能找回。若响应丢失，先检查列表并撤销不确定的 token，再生成替代项。重复管理请求 key 返回冲突，不会重新显示或静默复制密钥。

公共资源返回投影记录，不使用管理 API 的 {code,data} 包装。创建返回 201/Location/ETag；读取和修改返回 200/ETag；删除返回 204 无正文；列表返回 {items,hasMore,nextCursor}；命令返回 {action,resource,etag,idempotentReplay}；只读 Handler 按导出 schema 返回。保留 X-Request-Id 便于排查，不记录凭证。

3. 办公设备 CRUD/List 与业务接口

将下列代码保存为 crud.sh。安全设置 AURABOOT_BASE_URL、AURABOOT_APP_ID、AURABOOT_TOKEN，然后在开发环境执行 bash crud.sh。脚本依次验证身份、登记设备、读取/修改、过滤分页、分配设备和页面统计，最后另建并删除一台可用设备；已分配设备保留供检查。需要 Bash、curl、jq、Python 3，以及上节授权。不要输出环境变量或启用 shell tracing。

#!/usr/bin/env bash
set -euo pipefail
# Requires Bash, curl, jq and Python 3. Never enable shell tracing.
: "${AURABOOT_BASE_URL:?Set the operator-provided HTTPS origin}"
: "${AURABOOT_APP_ID:?Set the application ID delivered with the token}"
: "${AURABOOT_TOKEN:?Load the integration token from your secret manager}"
BASE=${AURABOOT_BASE_URL%/}
RESOURCE=office.devices
TASK_DIR=$(mktemp -d); chmod 700 "$TASK_DIR"; umask 077
trap 'rm -rf "$TASK_DIR"' EXIT
# Production requires HTTPS. Only isolated local development may use loopback HTTP.
python3 - <<'CHECK'
import os, urllib.parse
u=urllib.parse.urlsplit(os.environ['AURABOOT_BASE_URL'])
assert (u.scheme=='https' or (u.scheme=='http' and u.hostname in ('localhost','127.0.0.1')))
assert u.hostname and not u.username and not u.password and not u.query and not u.fragment and u.path in ('','/')
t=os.environ['AURABOOT_TOKEN']; assert t and '\r' not in t and '\n' not in t
CHECK
# Keep the token out of curl's command-line arguments and terminal output.
python3 - <<'AUTH' > "$TASK_DIR/auth.headers"
import os
print('Authorization: Bearer '+os.environ['AURABOOT_TOKEN'])
AUTH
new_key() { python3 -c 'import uuid; print(uuid.uuid4())'; }
etag() { awk 'tolower($1)=="etag:" {sub(/\r$/, ""); $1=""; sub(/^ /, ""); print}' "$1"; }
curl --fail-with-body -sS -H @"$TASK_DIR/auth.headers" "$BASE/api/open/v1/whoami" > "$TASK_DIR/identity.json"
jq -e --arg app "$AURABOOT_APP_ID" '.applicationPid == $app' "$TASK_DIR/identity.json" > /dev/null
# Persist each key, exact body and ETag before a write in a real integration.
# On uncertain transport failure, repeat the SAME intent. This sample has no auto-retry.
CREATE_KEY=$(new_key)
jq -n --arg code "LAPTOP-$(new_key)" '{assetCode:$code,name:"Office laptop",location:"HQ"}' > "$TASK_DIR/create.json"
curl --fail-with-body -sS -D "$TASK_DIR/create.headers" \
 -H @"$TASK_DIR/auth.headers" -H 'Content-Type: application/json' \
 -H "Idempotency-Key: $CREATE_KEY" --data-binary @"$TASK_DIR/create.json" \
 "$BASE/api/open/v1/resources/$RESOURCE" > "$TASK_DIR/created.json"
PID=$(jq -er '.pid' "$TASK_DIR/created.json")
jq -e '.status=="available" and .name=="Office laptop"' "$TASK_DIR/created.json" > /dev/null
curl --fail-with-body -sS -D "$TASK_DIR/get.headers" -H @"$TASK_DIR/auth.headers" \
 "$BASE/api/open/v1/resources/$RESOURCE/$PID" > "$TASK_DIR/current.json"
ETAG=$(etag "$TASK_DIR/get.headers"); test -n "$ETAG"
UPDATE_KEY=$(new_key)
printf '%s' '{"name":"Office laptop verified","serialNumber":null}' > "$TASK_DIR/update.json"
curl --fail-with-body -sS -X PATCH -D "$TASK_DIR/update.headers" \
 -H @"$TASK_DIR/auth.headers" -H 'Content-Type: application/json' \
 -H "Idempotency-Key: $UPDATE_KEY" -H "If-Match: $ETAG" \
 --data-binary @"$TASK_DIR/update.json" "$BASE/api/open/v1/resources/$RESOURCE/$PID" > "$TASK_DIR/updated.json"
ETAG=$(etag "$TASK_DIR/update.headers"); test -n "$ETAG"
jq -e '.name=="Office laptop verified" and .serialNumber==null' "$TASK_DIR/updated.json" > /dev/null
# Walk all authorized pages; the cursor is opaque and is not a synchronization watermark.
CURSOR=''; FOUND=0
while :; do
 ARGS=(--data-urlencode 'limit=20' --data-urlencode 'sort=name' --data-urlencode 'direction=ASC'
       --data-urlencode 'filters=[{"field":"location","operator":"EQ","value":"HQ"}]')
 if test -n "$CURSOR"; then ARGS+=(--data-urlencode "cursor=$CURSOR"); fi
 curl --fail-with-body -sS -G -H @"$TASK_DIR/auth.headers" "${ARGS[@]}" \
  "$BASE/api/open/v1/resources/$RESOURCE" > "$TASK_DIR/page.json"
 if jq -e --arg pid "$PID" '.items | any(.pid==$pid)' "$TASK_DIR/page.json" > /dev/null; then FOUND=1; fi
 if test "$(jq -r '.hasMore' "$TASK_DIR/page.json")" = false; then break; fi
 NEXT=$(jq -er '.nextCursor | select(length>0)' "$TASK_DIR/page.json"); test "$NEXT" != "$CURSOR"; CURSOR=$NEXT
done
test "$FOUND" = 1
# Explicit business API: native assignment state transition, same resource ETag and grant.
ASSIGN_KEY=$(new_key)
jq -n --arg pid "$PID" --arg person "${AURABOOT_ASSIGNED_TO:-External integration operator}" \
 '{targetPid:$pid,input:{assignedTo:$person}}' > "$TASK_DIR/assign.json"
curl --fail-with-body -sS -D "$TASK_DIR/assign.headers" \
 -H @"$TASK_DIR/auth.headers" -H 'Content-Type: application/json' \
 -H "Idempotency-Key: $ASSIGN_KEY" -H "If-Match: $ETAG" --data-binary @"$TASK_DIR/assign.json" \
 "$BASE/api/open/v1/actions/office.devices.assign:execute" > "$TASK_DIR/assigned.json"
jq -e '.resource.status=="in_use" and .idempotentReplay==false' "$TASK_DIR/assigned.json" > /dev/null
# A registered no-target, read-only handler counts only one authorized page, not total inventory.
curl --fail-with-body -sS -H @"$TASK_DIR/auth.headers" -H 'Content-Type: application/json' \
 --data '{"input":{"limit":20}}' "$BASE/api/open/v1/actions/office.devices.page-summary:execute" > "$TASK_DIR/summary.json"
jq -e '.countOnPage>=1 and (.hasMore|type)=="boolean"' "$TASK_DIR/summary.json" > /dev/null
# Delete a separate AVAILABLE example; preserve the assigned device as a reviewable business trace.
jq -n --arg code "TEMP-$(new_key)" '{assetCode:$code,name:"Temporary office device",location:"HQ"}' > "$TASK_DIR/delete-example.json"
TEMP_KEY=$(new_key)
curl --fail-with-body -sS -D "$TASK_DIR/temp.headers" -H @"$TASK_DIR/auth.headers" \
 -H 'Content-Type: application/json' -H "Idempotency-Key: $TEMP_KEY" \
 --data-binary @"$TASK_DIR/delete-example.json" "$BASE/api/open/v1/resources/$RESOURCE" > "$TASK_DIR/temp.json"
TEMP_PID=$(jq -er '.pid' "$TASK_DIR/temp.json"); TEMP_ETAG=$(etag "$TASK_DIR/temp.headers"); test -n "$TEMP_ETAG"
DELETE_KEY=$(new_key)
STATUS=$(curl --fail-with-body -sS -X DELETE -o "$TASK_DIR/delete.body" -w '%{http_code}' \
 -H @"$TASK_DIR/auth.headers" -H "Idempotency-Key: $DELETE_KEY" -H "If-Match: $TEMP_ETAG" \
 "$BASE/api/open/v1/resources/$RESOURCE/$TEMP_PID")
test "$STATUS" = 204
printf 'Office CRUD/List, assignment and page summary completed.\n'

接口对应关系：POST /resources/office.devices 登记；GET 同一路径查询列表；GET /resources/office.devices/{pid} 读取；PATCH 同一路径修改；DELETE 同一路径删除。所有路径前缀为 /api/open/v1。分配接口为 POST /api/open/v1/actions/office.devices.assign:execute，正文为 {"targetPid":"设备PID","input":{"assignedTo":"员工姓名"}}。

并发与幂等：修改、删除、设备分配需带原样保留（含引号）的资源 ETag，作为 If-Match。每次写入前持久保存唯一 Idempotency-Key、精确正文和适用 ETag；超时且结果不明时重发同一次意图，不换 key。key 在安装/路由范围内保留 24 小时；不匹配或过期会冲突，成功重放返回 Idempotent-Replay: true。重放仍检查当前授权。412 必须重新读取并协调业务意图，不能直接换新 ETag 盲重试。PATCH 省略字段不修改，显式 null 只清空允许为空且可写的字段。

分页边界：保持过滤、排序、方向和每页条数不变，使用不透明 nextCursor 继续；合同/策略变化或游标过期需重新开始。List 不是稳定全量快照，List 加事件不承诺无损同步；同步水位、增量补拉及快照边界不在本版范围。

业务接口为显式发布的 POST 合同，不是任意内部 Controller 或在线脚本。分配沿用绑定资源的 ETag、当前行字段权限、声明影响字段及原生状态规则。只读 Handler 不带 targetPid/If-Match/Idempotency-Key。另行发布的 NamedQuery 接受类型化参数，不接受 SQL。TypeScript SDK 支持直接 token 和资源 CRUD/List/query，本例业务接口使用 HTTP。

3.1 将已有内部接口发布给外部

管理员进入“开放平台 → 公共业务接口 → 内部接口对外发布”，选择已登记机器适配的 Controller 来源，再绑定已发布的资源、查询或业务动作。目录显示真实内部方法/路径及可开放资格；未登记适配的接口禁止直接发布。这不是任意 URL 转发，也不会模拟管理员调用。

办公设备示例：详情/列表/创建/修改/删除来源绑定 office.devices；命令执行来源绑定已发布的 office.devices.assign；命名查询来源必须绑定另行发布的类型化查询。校验来源和合同、保存草稿并确认发布后，在安装的“数据授权”选择该外部接口并授予调用权；安装还需新增其调用 Scope，并保留绑定资源/查询/业务动作的 Scope 和授权。仅有 token 或仅有接口授权均不能取得数据访问权。

示例公开编码方法及地址正文与前置条件
office.devices.lookupGET /api/open/v1/endpoints/office.devices.lookup/{recordPid}无正文，返回投影记录和 ETag
office.devices.searchGET /api/open/v1/endpoints/office.devices.search使用前述 limit/cursor/filters/sort/direction
office.devices.registerPOST /api/open/v1/endpoints/office.devices.register创建 JSON 与 Idempotency-Key，返回 201
office.devices.editPATCH /api/open/v1/endpoints/office.devices.edit/{recordPid}修改 JSON、If-Match 与 Idempotency-Key
office.devices.removeDELETE /api/open/v1/endpoints/office.devices.remove/{recordPid}无正文，If-Match 与 Idempotency-Key，返回 204
office.devices.allocatePOST /api/open/v1/endpoints/office.devices.allocate分配动作正文 targetPid/input、If-Match 与 Idempotency-Key

这些示例别名必须显式发布，以管理员交付的地址及导出 OpenAPI/类型为准。内部 PUT 可明确适配为外部 PATCH；对外使用公开字段和返回合同，不照搬内部 Controller 包装或字段名。安装授权更新后，原定期/永久集成 token 直接可用。

POST /api/open/v1/endpoints/office.devices.register

幂等 key 按外部接口和精确意图保管；412 后重新读取并协调，409 时请管理员检查已固定的来源/数据合同。已发布地址不能静默改变语义。撤销接口或绑定数据授权、停用父对象、撤销/轮换 token 均会影响后续请求。写入沿用原生业务事件链，不把任意 HTTP 200 自动转换为业务事件。

4. 订阅模型事件

  1. 管理员发布设备事件，授予安装读取、行/字段权限和事件目录 scope。
  2. 外部部署有效 HTTPS 接收端，单独保管 Webhook 签名密钥，它不是 API token。
  3. 进入安装卡片的“模型通知”，选择事件/版本、HTTPS 接收地址和签名密钥，按需分别创建新增、修改和删除订阅。
  4. 触发真实 CRUD 或分配，检查投递记录及接收端持久 inbox。通用测试通知不能证明模型字段投影与授权正确。

GET /api/open/v1/event-catalog 返回当前事件合同（需要相应 scope）。本例为 open.resource.office.devices.created、open.resource.office.devices.updated、open.resource.office.devices.deleted，schemaVersion 为 1。每次投递/重放均检查当前发布、来源及安装授权。通知如下：

POST /webhooks/auraboot
Content-Type: application/json
X-Webhook-Event: open.resource.office.devices.updated
X-Webhook-Event-Version: 1
X-Webhook-Timestamp: 1792020000
X-Webhook-Delivery: delivery_public_pid
X-Webhook-Signature: sha256=LOWERCASE_HEX_HMAC

{"id":"event_public_id","type":"open.resource.office.devices.updated","schemaVersion":1,"occurredAt":"2026-10-15T00:00:00Z","subject":{"type":"office.devices","pid":"record_public_pid"},"recordVersion":2,"correlationId":"request_correlation","data":{"pid":"record_public_pid","assetCode":"LAPTOP-001","name":"Office laptop","status":"in_use","location":"HQ","assignedTo":"External integration operator"}}

正文只包含当前允许的公开字段，字段缺失不等于 null，也不表示清空下游值。删除事件含投影后的删除前记录和更新的版本。通知采用至少一次投递，可能重复、乱序；接收方保存事件 ID、每条记录版本和删除标记，版本不保证连续。经授权的 UI/导入/Command 变更也可能产生事件。权限收窄后，下游按自己的数据保留策略清理不再授权的数据；重放不恢复历史权限。

5. 验签与可靠接收

解析 JSON 前验证 sha256=hex(HMAC-SHA256(UTF8(secret), ASCII(timestamp)+b"."+raw_body))。使用常量时间比较并限制时间窗口（示例 ±300 秒），保持时钟同步；校验事件类型、schema、资源身份、版本及投影字段类型。下面的白名单针对办公设备，应按实际导出合同和授权调整。HTTPS 反向代理需限制请求体、请求/读取超时及并发。

保存为 receiver.py，设置稳定的 AURABOOT_CONSUMER_KEY、密钥管理中的 AURABOOT_WEBHOOK_SECRET 和绝对持久路径 INBOX_DB。反向代理仅将 /webhooks/auraboot 转发到 loopback 8099，运行 python3 receiver.py；另一个 worker 定期运行 python3 receiver.py --drain。可选旧签名密钥 AURABOOT_WEBHOOK_PREVIOUS_SECRET 必须配显式 Unix 截止 AURABOOT_WEBHOOK_PREVIOUS_UNTIL，到期移除旧密钥。

#!/usr/bin/env python3
"""Python 3 stdlib office-device receiver and atomic inbox worker; HTTPS proxy required."""
import hashlib, hmac, json, os, sqlite3, stat, sys, time
from http.server import BaseHTTPRequestHandler, HTTPServer
DB = os.environ['INBOX_DB']
CONSUMER = os.environ['AURABOOT_CONSUMER_KEY']
SECRET = os.environ['AURABOOT_WEBHOOK_SECRET'].encode('utf-8')
assert os.path.isabs(DB) and CONSUMER and SECRET, 'Persistent absolute DB path and secrets required'
RESOURCE = 'office.devices'
TYPES = {f'open.resource.{RESOURCE}.{suffix}' for suffix in ('created','updated','deleted')}
FIELDS = {'pid','assetCode','name','status','location','serialNumber','assignedTo'}
def connect():
    # Create private storage and reject an unsafe existing path instead of changing its permissions.
    try:
        fd = os.open(DB, os.O_CREAT | os.O_EXCL | os.O_WRONLY, 0o600); os.close(fd)
    except FileExistsError:
        info = os.lstat(DB)
        if not stat.S_ISREG(info.st_mode) or info.st_mode & 0o077:
            raise ValueError('Inbox storage must be a private regular file')
    db = sqlite3.connect(DB, timeout=5)
    db.execute('PRAGMA journal_mode=WAL')
    db.execute('CREATE TABLE IF NOT EXISTS inbox (consumer TEXT, id TEXT, body BLOB, done INTEGER DEFAULT 0, PRIMARY KEY(consumer,id))')
    db.execute('CREATE TABLE IF NOT EXISTS projection (consumer TEXT, resource TEXT, pid TEXT, version INTEGER, deleted INTEGER, data TEXT, PRIMARY KEY(consumer,resource,pid))')
    return db

def validate(event, headers):
    if not isinstance(event, dict) or event.get('type') not in TYPES:
        raise ValueError('Unsubscribed event')
    if (headers.get('X-Webhook-Event') != event['type'] or headers.get('X-Webhook-Event-Version') != '1'
        or type(event.get('schemaVersion')) is not int or event['schemaVersion'] != 1
        or type(event.get('recordVersion')) is not int or not 1 <= event['recordVersion'] <= 9223372036854775807):
        raise ValueError('Schema or version mismatch')
    subject, data = event.get('subject'), event.get('data')
    if not isinstance(subject, dict) or subject.get('type') != RESOURCE or not isinstance(data, dict):
        raise ValueError('Invalid resource')
    for identity in (event.get('id'), subject.get('pid')):
        if not isinstance(identity,str) or not 1 <= len(identity) <= 200 or any(ord(c)<33 for c in identity):
            raise ValueError('Invalid identity')
    if set(data) - FIELDS or data.get('pid') != subject['pid']:
        raise ValueError('Unexpected field or identity')
    for key, value in data.items():
        if value is not None and (not isinstance(value,str) or len(value)>10000):
            raise ValueError('Invalid field type')
    # Adapt required fields to the actual projected contract and current installation policy.
    if any(key in data and data[key] is None for key in ('pid','assetCode','name')):
        raise ValueError('Required field cannot be null')

def drain():
    db = connect()
    try:
        while True:
            with db:
                db.execute('BEGIN IMMEDIATE')
                row = db.execute('SELECT id,body FROM inbox WHERE consumer=? AND done=0 ORDER BY rowid LIMIT 1', (CONSUMER,)).fetchone()
                if row is None: return
                event = json.loads(row[1]); subject = event['subject']
                deleted = int(event['type'].endswith('.deleted'))
                db.execute('INSERT INTO projection VALUES (?,?,?,?,?,?) ON CONFLICT(consumer,resource,pid) DO UPDATE SET version=excluded.version,deleted=excluded.deleted,data=excluded.data WHERE excluded.version>projection.version',
                    (CONSUMER,subject['type'],subject['pid'],event['recordVersion'],deleted,json.dumps(event['data'])))
                db.execute('UPDATE inbox SET done=1 WHERE consumer=? AND id=?', (CONSUMER,row[0]))
    finally: db.close()

class Receiver(BaseHTTPRequestHandler):
    def log_message(self, *_): pass  # Never log bodies, secrets or authorization headers.
    def do_POST(self):
        if self.path != '/webhooks/auraboot': self.send_error(404); return
        try:
            length = int(self.headers.get('Content-Length','0'))
            if not 0 < length <= 1048576: self.send_error(413); return
            raw = self.rfile.read(length)
            if len(raw) != length: raise ValueError('Incomplete body')
            stamp = self.headers.get('X-Webhook-Timestamp','')
            if not stamp.isascii() or not stamp.isdecimal() or len(stamp)>12 or abs(time.time()-int(stamp))>300:
                self.send_error(401); return
            signature = self.headers.get('X-Webhook-Signature','')
            if len(signature)!=71 or not signature.startswith('sha256='):
                self.send_error(401); return
            keys = [SECRET]
            previous = os.environ.get('AURABOOT_WEBHOOK_PREVIOUS_SECRET')
            # Previous signing key is accepted only until an explicit local Unix deadline.
            if previous and time.time() < int(os.environ['AURABOOT_WEBHOOK_PREVIOUS_UNTIL']): keys.append(previous.encode('utf-8'))
            if not any(hmac.compare_digest(signature, 'sha256='+hmac.new(k,stamp.encode('ascii')+b'.'+raw,hashlib.sha256).hexdigest()) for k in keys):
                self.send_error(401); return
            event = json.loads(raw); validate(event,self.headers)
            db = connect()
            try:
                with db:
                    old = db.execute('SELECT body FROM inbox WHERE consumer=? AND id=?', (CONSUMER,event['id'])).fetchone()
                    if old is not None:
                        # Same event ID must retain its record identity and version. Projection may narrow on replay.
                        prior = json.loads(old[0])
                        if any(prior.get(k)!=event.get(k) for k in ('type','subject','recordVersion','schemaVersion')):
                            raise ValueError('Conflicting duplicate event')
                    else: db.execute('INSERT INTO inbox(consumer,id,body) VALUES(?,?,?)', (CONSUMER,event['id'],raw))
            finally: db.close()
            self.send_response(204); self.end_headers()  # Durable inbox committed before acknowledgement.
        except (ValueError,UnicodeError,KeyError,TypeError): self.send_error(400)
        except sqlite3.Error: self.send_error(503)

if __name__=='__main__':
    if sys.argv[1:]==['--drain']: drain()
    elif sys.argv[1:]: raise SystemExit('Usage: receiver.py [--drain]')
    else: HTTPServer(('127.0.0.1',int(os.environ.get('PORT','8099'))),Receiver).serve_forever()

提交 inbox 后才返回 204，存储失败返回 503 让平台重试。重复事件身份/版本只接受一次。worker 在同一事务中更新最新投影和 inbox 完成状态，保留删除标记并忽略旧版本。它是最近接收事件的本地视图，不是全量同步业务记录或数据擦除协议；外部业务副作用需要自己的事务 outbox/幂等机制。

6. 失败重试、死信与重放

结果处理方式
400按导出合同修正输入，不重复发送相同错误数据。
401 / 403请管理员检查到期、轮换截止、撤销、父状态及当前授权；集成 token 不通过 OAuth 换取恢复。
409 / 412检查意图、来源或合同冲突；并发冲突需重新读取并协调，不静默换 key 或 ETag。
429遵循返回的 Retry-After，做有界退避和抖动，保留原写入意图。
超时 / 5xx有界重试且保持原写入意图；持续失败时提供 requestId 和脱敏元数据排查。

Webhook 失败采用指数退避和抖动，间隔上限一小时。maxRetries 表示失败尝试总预算，不是额外重试次数；HTTP 4xx/5xx 和传输失败消耗预算，SSRF/配置错误或模型授权撤销可能立即进入死信。不跟随重定向。接收端可靠落盘后尽快返回 2xx。同一租户、同一接收端来源跨订阅限制在途请求，慢端隔离已有验证，但开发测量不是生产吞吐或延迟承诺。

  1. 在安装投递日志中找到失败/死信，记录投递 ID、事件 ID、requestId、状态和时间，不保留密钥或敏感正文。
  2. 修复接收服务、数据库或 schema；来源/发布/授权问题由管理员处理。
  3. 有权限管理员点击“重放”，阅读可能重复产生下游副作用的提示并确认。机器 token 不能管理重放。
  4. 确认投递成功，接收方 inbox 对同一事件只处理一次。重放不生成新业务事件，也不绕过当前授权。

管理员重放 API 为 POST /api/open-platform/installations/{installationPid}/webhook-deliveries/{deliveryPid}/replay，使用管理登录态和 CSRF 策略，返回管理包装。建议使用管理页。生产频率、延迟、支持方式和版本兼容需另外约定。

7. 既有 OAuth 接入

既有 client-credentials 接入继续支持：向 POST /oauth2/token 提交表单 grant_type=client_credentials、client_id、client_secret 和已授予的空格分隔 scope，或使用 HTTP Basic 客户端认证且不重复表单凭据。安全缓存 access_token 并遵循 expires_in。没有 refresh-token 流程，到期重新换取；401 可换取一次并重试原意图，持续失败需管理员处理。安装 scope 修改会撤销已有 OAuth token，需重新换取。永久集成 token 不改变 OAuth 的有效期或请求 scope 上限。
