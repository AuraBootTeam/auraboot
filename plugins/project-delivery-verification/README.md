# 项目交付核验扩展

这是项目管理模板的可选扩展示例：通用 DSL 页面调用独立 PF4J Handler，经宿主提供的 `DataAccessor` 读取当前租户业务数据并写回核验快照。基础 `project-management` 仍然是 config-only，不依赖本插件安装。

## 使用

企业版七场景启动器在显式初始化时编译、加载本插件并导入配置；恢复预览不覆盖已有业务记录。已有环境加入插件需要走显式更新和配置导入，不能只把 JSON 导入一个没有加载 Handler 的后端。

1. 在“项目交付 → 交付验收”创建真实验收单，选择项目、填写范围和金额。材料暂缺时可保存草稿。
2. 在“项目交付 → 交付核验”新建记录，填写例如“华辰制造 · 第一阶段交付核验”，选择上一步验收单并保存。
3. 打开核验记录，点击“执行交付核验”。结果、预算快照和核验时间自动刷新；查看关联验收单可回到原业务对象。
4. 缺材料或范围时，回到验收单编辑补正。预算不足时核对项目预算与其他已通过验收金额。回到核验记录重新执行，系统重新读取业务数据。
5. 管理员可查看核验操作动态。只读角色 `tdv_viewer` 只能查看；负责人角色 `tdv_manager` 可以创建和执行，不授予租户管理员权限。

## 判断边界

| 检查 | 通过条件 | 不通过时 |
|---|---|---|
| 材料 | 验收材料列表非空 | 请上传交付材料；不声称检查文件内容真实性 |
| 范围 | 已填写验收范围 | 请填写完成标准 |
| 金额 | 正数，精确到人民币分 | 不接受负数、零、非法数值或不足一分的精度 |
| 预算 | 本次金额 ≤ 项目预算 − 其他已通过验收金额 | 预算缺失时明确要求配置；超出一分也阻断 |

当前验收已通过时不会重复计入“其他已验收金额”。草稿、待补正、审批中的金额不计为已消耗；本能力不提供并发预算预占或付款承诺。结果是核验时的建议快照，不自动提交、通过、驳回或更改审批，也不保证后续并发操作仍满足预算。材料、范围、金额、预算或已验收记录变化后必须重跑。

Handler 不使用客户端提交的结论或金额，没有直接 SQL、任意 HTTP、模型 API 或文件写入。读取权限、租户隔离、事务与审计沿用宿主命令边界。重复执行更新同一核验记录，不生成额外结果记录；干跑不写快照。

## 开发与验证

构建必须使用当前宿主的 `platform-plugin-api` JAR，并通过 Workspace 的受管 Gradle 入口传入 `-PplatformPluginApiJar=<absolute-api-jar>`。构建产物是 `backend/build/libs/delivery-verification-plugin-1.0.0.jar`；部署前检查 `META-INF/extensions.idx` 包含 `VerifyDeliveryHandler`。

算法、精度、拒绝与干跑测试位于 `backend/src/test`。真实安装、表单补正、预算边界、普通负责人/只读权限及跨租户验证复用 Enterprise 场景 runner 的 `verification` profile，对应 `web-admin/tests/e2e/project-management/delivery-verification-real.spec.ts`。测试文件存在不代表已执行，实际结论以本轮证据为准。

## 核验记录的当前有效性

验收详情的核验 Tab 通过 `tdv_acceptance_verifications` 读取真实快照。查询先校验目标验收单读取权限，材料更新时间晚于核验时间时返回只读派生状态 `stale`（资料已更新 · 需复核）。原核验状态、时间及通过项数不被重写；通过项数是检查当时的快照，不代表更新后的材料仍有效。重新核验后由服务端时间重新判定。未安装本可选插件时，原有 `tdv.check.read` 权限门继续隐藏该 Tab。
